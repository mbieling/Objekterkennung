## Spacing Scale

Declared values (multiples of 4 only — Tailwind default scale):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between icon and label |
| sm | 8px | Compact spacing between stacked UI elements |
| md | 16px | Default padding inside cards; gap between buttons |
| lg | 24px | Section padding within the camera view; vertical rhythm |
| xl | 32px | Page-level top/bottom padding (`py-8`) |
| 2xl | 48px | Vertical separation between camera section and result section |
| 3xl | 64px | Not used in Phase 7 |

Exceptions:
- Touch targets (camera capture button, primary CTA): minimum 44px height to meet WCAG 2.5.5 on mobile — use `h-12` (48px)
- Video framing overlay: `inset-[10%]` over a `max-w-sm` container — approximately 80% of container width (D-07)

Source: 8-point grid standard + CONTEXT.md D-07.

- The "Suchen"-Button (confirm and submit search, D-08)

- "Wiederholen"-Button (uses `variant="outline"`)

- Spinner (inherits foreground color via `animate-spin`)

Secondary semantic color for error states: `--destructive` (`0 84.2% 60.2%`) — used only for shadcn `Alert` with `variant="destructive"` when the search fails (D-11) or getUserMedia permission is denied (D-05).

## Interaction Contract

### State Machine

The `CameraCapture.tsx` client component implements the following state machine
(type: `SearchPhase`). Each state maps to exactly one visual layout:

| State | Visual Layout |
|-------|--------------|
| `idle` | Startbildschirm: "Kamera starten"-Button (primary) + File-Input-Trigger (ghost) side by side |
| `requesting` | Skeleton placeholder (same area as video) + "Kamera wird aktiviert..."-Label |
| `previewing` | Live-Video mit Framing-Overlay + "Aufnehmen"-Button (primary, 48px height) |
| `captured` | Standbild `<img>` mit Framing-Overlay ausgeblendet + "Suchen"-Button (primary) + "Wiederholen"-Button (outline) |
| `searching` | Spinner (`Loader2 animate-spin`) + "Suche läuft..."-Text, kein Video, kein Bild |
| `result` | `<pre className="text-xs overflow-auto bg-muted p-4 rounded-lg">` mit JSON-Output |
| `error` | `Alert variant="destructive"` mit Fehlermeldung + "Neu aufnehmen"-Button (outline) |

Transitions:
- `idle` → `requesting`: Kamera-Button-Click
- `requesting` → `previewing`: getUserMedia resolved
- `requesting` → `idle` + `error` shown: getUserMedia rejected (D-05) — File-Input bleibt sichtbar
- `previewing` → `captured`: "Aufnehmen"-Button-Click (canvas.toBlob)
- `captured` → `previewing`: "Wiederholen"-Button-Click
- `captured` → `searching`: "Suchen"-Button-Click
- `searching` → `result`: POST /api/search HTTP 200 (D-10)
- `searching` → `error`: HTTP error, Netzwerkfehler, AbortController-Timeout nach 30s (D-09, D-11)
- `error` → `idle`: "Neu aufnehmen"-Button-Click

Source: CONTEXT.md D-03 bis D-11 + RESEARCH.md Pattern 1 — pre-populated.

### Video-Element

```
<video playsInline muted autoPlay ref={videoRef}>
```

Mandatory attributes: `playsInline` (iOS Safari Pflicht), `muted` (iOS autoplay Pflicht).
Container: `relative w-full aspect-[4/3] max-w-sm mx-auto` — Portrait-freundlich, zentriert.
Object fit: `object-cover` — füllt den Container ohne Letterboxing.

### Framing-Overlay (D-07)

Absolut positioniertes `div` über dem Video-Element:
```
className="absolute inset-[10%] border-2 border-white/70 rounded-xl pointer-events-none"
```
Keine zusätzliche Beschriftung innerhalb des Overlays (D-07: minimalistisch).
`pointer-events-none` — Overlay blockiert keine Kamera-Button-Interaktion.

### File-Input (D-06)

Immer sichtbar — auch wenn getUserMedia läuft. Trigger: `Button variant="ghost"` mit Upload-Icon.
Hidden `<input type="file" accept="image/*" capture="environment" className="hidden">`.
Sichtbar in allen States außer `searching` (wo keinerlei Eingabe möglich ist).

### Bildkomprimierung (Claude's Discretion)

Canvas-Resize auf max. 1024px Breite, JPEG 0.85 Qualität (`canvas.toBlob('image/jpeg', 0.85)`).
Dies ist unsichtbar für den Nutzer — kein UI-Indikator nötig.

### 30s Timeout (D-09)

`AbortController` mit `setTimeout(() => controller.abort(), 30_000)`.
Bei Abort-Error: State → `error` mit Fehlermeldung "Suche hat zu lange gedauert. Bitte erneut versuchen."

### Homepage-Erweiterung (D-02)

`src/app/page.tsx` bekommt zwei Buttons nebeneinander:
- Layout: `flex gap-4 flex-wrap justify-center`
- Button 1 (primary): "Teil hochladen" → `/upload`
- Button 2 (outline): "Teil suchen" → `/search`

## Layout Contract

### `/search` Page Layout

```
<main className="min-h-screen bg-background py-8 px-4">
  <div className="max-w-md mx-auto">
    <h1 className="text-2xl font-semibold mb-8">Bauteil fotografieren</h1>
    <CameraCapture />   {/* Client Component */}
  </div>
</main>
```

`max-w-md` (448px) — narrow column optimal für Mobile-first, passt zu shadcn Card.
Pattern übernommen von `/upload` (`max-w-4xl` dort, aber Camera UI ist schmaler weil kein Metadaten-Formular).

### CameraCapture Component Layout (per State)

**idle:**
```
<Card>
  <CardContent className="pt-6 flex flex-col gap-4 items-center">
    [Kamera-Button primary, volle Breite]
    [File-Input-Trigger ghost, volle Breite]
  </CardContent>
</Card>
```

**previewing:**
```
<div className="flex flex-col gap-4">
  [Video-Container mit Overlay, max-w-sm mx-auto]
```

## Accessibility Contract

| Element | Requirement |
|---------|------------|
| Camera Button | `aria-label="Kamera starten"` when icon-only; text label preferred |
| Video element | `aria-label="Kamera-Vorschau"` |
| Framing overlay div | `aria-hidden="true"` (decorative) |
| File input | `<label>` association via `htmlFor`; visible trigger button |
| Loader spinner | `aria-live="polite"` on parent container; `aria-label="Suche läuft"` on spinner |
| Alert (error) | shadcn Alert uses `role="alert"` natively — no extra work needed |
| Touch targets | All interactive elements minimum 44px height (`h-11` or `h-12`) |

Source: WCAG 2.5.5 (target size) + RESEARCH.md Security Domain + shadcn Alert semantics.
