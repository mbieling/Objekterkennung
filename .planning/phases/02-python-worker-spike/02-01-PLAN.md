```dockerfile
FROM continuumio/miniconda3:latest

# Systemabhängigkeiten für OSMesa (RESEARCH.md Pitfall 3: libGL muss vorhanden sein)
RUN apt-get update && apt-get install -y \
    libgl1-mesa-glx \
    libglib2.0-0 \
    libgomp1 \
    --no-install-recommends && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# OSMesa erzwingen — VOR allen VTK/OCC-Imports (RESEARCH.md Pitfall 1)
# Gilt auch für docker exec -Aufrufe außerhalb des Entrypoints
ENV VTK_DEFAULT_OPENGL_WINDOW=vtkOSOpenGLRenderWindow

# conda: pythonocc-core 7.9.3 aus conda-forge
# NICHT zusätzlich vtk via conda — Pitfall 5: conda-vtk vs. pip-vtk Konflikt
COPY environment.yml .
RUN conda env update -n base -f environment.yml && conda clean -afy

# pip: restliche Pakete (kein pythonocc — das ist in conda)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# DINOv2-Modell beim Build cachen — kein Download zur Laufzeit (RESEARCH.md Pitfall 2)
# ~330 MB; Build-Zeit ~3 Minuten beim ersten Mal
ENV TRANSFORMERS_CACHE=/app/model_cache
RUN python -c "from transformers import AutoImageProcessor, AutoModel; \
    AutoModel.from_pretrained('facebook/dinov2-base'); \
    AutoImageProcessor.from_pretrained('facebook/dinov2-base')"

COPY . .
```

<threat_model>
## Trust Boundaries

| Boundary | Beschreibung |
|----------|--------------|
| Entwickler-Host → Docker-Container | Env-Vars via `--env-file worker/.env`, nie als Docker-Build-ARGs |
| Container → Neon PostgreSQL | DATABASE_URL via Env-Var; TLS via sslmode=require in URL |
| Container → AWS S3 | AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY via Env-Var |
| Container → HuggingFace Hub | Nur beim Build (TRANSFORMERS_CACHE); zur Laufzeit kein Outbound nötig |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|-----------|
| T-02-01 | Information Disclosure | worker/Dockerfile | mitigate | DATABASE_URL und AWS-Secrets dürfen NIEMALS als ARG oder ENV im Dockerfile stehen — nur via `--env-file` zur Laufzeit übergeben; Dockerfile im Repo ohne Secrets |
| T-02-02 | Information Disclosure | worker/.env | mitigate | worker/.env (echte Credentials) in .gitignore eintragen; nur worker/.env.example (Dummy-Werte) committen |
| T-02-03 | Tampering | worker/testdata/sample.step | accept | Testdatei kommt aus eigenem Repo; keine externe Input-Quelle im Spike; Risiko minimal |
| T-02-04 | Denial of Service | Dockerfile DINOv2-Download | mitigate | Modell beim Build cachen (TRANSFORMERS_CACHE); verhindert fehlschlagenden Laufzeit-Download in restriktiven Umgebungen |
| T-02-05 | Information Disclosure | conda/pip Supply Chain | accept | continuumio/miniconda3 ist offizielles Anaconda-Image; conda-forge ist vertrauenswürdige Community-Registry; für Spike akzeptabel; Produktion würde Image-Digest pinnen |
</threat_model>
