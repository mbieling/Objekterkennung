## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps within badges, gap between icon and label in dropdown items |
| sm | 8px | Row cell padding (vertical), gap between search field and tabs |
| md | 16px | Card/section padding, form field vertical spacing in Sheet, table cell horizontal padding |
| lg | 24px | Gap between page header and content area, Sheet internal section gaps |
| xl | 32px | Page-level horizontal padding on desktop |
| 2xl | 48px | Thumbnail size in table rows (48×48px — see exception below) |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Table thumbnail: 48×48px (fits the 2xl token exactly — intentional)
- Sheet thumbnail: 192×192px (fixed dimension per D-08 — outside normal scale, defined by decision)
- Touch targets for all interactive elements (buttons, dropdown triggers): minimum 44px height (accessibility floor)

## Typography

Matches established patterns from `src/app/upload/UploadForm.tsx` and shadcn/ui defaults.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 | Table cell text, form labels in Sheet, pagination info, dropdown items |
| Column Header | 14px (`text-sm`) | 400 (regular) | 1.25 | Column headers (`text-muted-foreground`) — color distinguishes from body, not weight |
| Heading | 18px (`text-lg`) | 600 (semibold) | 1.2 | Sheet title ("Bauteil bearbeiten"), page heading ("Teile-Katalog") |
| Caption | 12px (`text-xs`) | 400 (regular) | 1.4 | "Erstellt am"-timestamps, helper text below form fields, pagination count |

Two weights only: 400 (regular) and 600 (semibold).

Note: shadcn `TableHead` applies `text-muted-foreground text-sm` — the color shift (not a separate weight) is the visual distinction from body text. Do not apply `font-medium` (500) to column headers.

## Color

Sourced directly from `src/app/globals.css` CSS variables (shadcn slate base):

| Role | CSS Variable | Light Mode Value | Usage |
|------|-------------|-----------------|-------|
| Dominant (60%) | `--background` | `hsl(0 0% 100%)` — white | Page background, table background |
| Secondary (30%) | `--secondary` / `--muted` | `hsl(240 4.8% 95.9%)` — slate-50 | Table header row, Sheet background, tab bar background, pagination controls |

| Status value | Badge appearance | Tailwind classes |

| `processing` | Blue outline | `variant="outline" className="text-blue-600 border-blue-300"` |

## Interaction Contracts

### Tab Filtering

- Default tab on page load: "Alle"
- Tab switch: synchronous client-side filter of already-fetched data (no server refetch per tab change)
- Count badge in each tab: reflects current filtered count (updates live after edit/archive/delete)
- Tab value → SQL status filter mapping:
  - `all` → no filter
  - `ready` → `status = 'ready'`
  - `pending` → `status = 'pending'`
  - `failed` → `status = 'failed'`
  - `archived` → `status = 'archived'`

### Search Field

- Freetext input above table, inside the tab panel
- Filters client-side by `name` (case-insensitive) OR `part_number` (case-insensitive)
- Debounce: 300ms after last keystroke before filter applies
- Search applies within the active tab (tabs and search are composable filters)
- Placeholder: "Nach Bezeichnung oder Teilenummer suchen…"
- Clear button (X icon) appears when field is non-empty; click clears input and resets filter

### Pagination

- 20 rows per page (client-side slice of fetched data)
- Page state: React state (not URL query parameter — catalog is admin-only, bookmarking not required)
- Pagination resets to page 1 on tab change and on search input change
- Controls: Previous / page numbers / Next (shadcn `Pagination` component)
- Show "Zeige {from}–{to} von {total} Teilen" caption below pagination controls (text-xs text-muted-foreground)

### Edit Sheet

- Opens on "Bearbeiten" dropdown item click
- Slides in from right; background table dims via Sheet overlay (shadcn default behavior)
- After "Speichern":
  - Sheet stays open (does not close)
  - Table row for that part updates immediately (optimistic update: replace row data in local state)
  - Sonner toast: "Änderungen gespeichert." (success, duration 3s)
- On save API error:
  - Sheet stays open
  - Inline error below form: "Speichern fehlgeschlagen. Bitte erneut versuchen." (text-sm text-destructive)
- "Abbrechen" closes the Sheet without saving; no confirmation if form is dirty

### Archive Action

- Triggers immediately on "Archivieren" click (no confirmation dialog)
- Optimistic update: row status badge changes to "Archiviert" instantly
- If active tab is not "Alle" and not "Archiviert": row disappears from current tab view immediately
- On API error: row reverts; Sonner toast: "Archivieren fehlgeschlagen. Bitte erneut versuchen." (destructive)

### Delete Action

- Opens AlertDialog (no immediate action on menu click)
- User must click "Endgültig löschen" to confirm
- On confirm: row removed from table immediately (optimistic); API call deletes DB row + S3 objects
- On API error: row reappears; Sonner toast: "Löschen fehlgeschlagen. Bitte erneut versuchen." (destructive)
- Scope of S3 deletion: `{part_id}/original.step` in `parts-steps` bucket + `{part_id}/view_0.png` through `{part_id}/view_7.png` in `parts-thumbnails` bucket

### Retry Action ("↺ Neu starten")

- Visible in DropdownMenu only when `status === 'failed'`
- No confirmation dialog
- On click: sets row status to "Ausstehend" immediately (optimistic), calls enqueue endpoint
- On API error: reverts to "Fehlgeschlagen"; Sonner toast: "Neustart fehlgeschlagen. Bitte erneut versuchen." (destructive)

### Thumbnail Loading in Table

- For rows with `status === 'ready'`: fetch presigned URL from `/api/parts/[id]/thumbnail`, render `<img>`
- For rows with any other status: render `<Skeleton className="w-12 h-12 rounded-sm" />`
- Thumbnails are loaded lazily (only for visible rows) — use `loading="lazy"` on `<img>`

### Thumbnail in Sheet

- For parts with `status === 'ready'` and available thumbnail: 192×192px `<img>` with `object-contain`
- For parts with `status !== 'ready'` or no thumbnail URL yet:
  - `<Skeleton className="w-48 h-48 rounded-md" />` rendered underneath
  - Text overlay (positioned absolute, centered): "Thumbnail wird verarbeitet…" (text-xs text-muted-foreground)

## URL and Route Decisions

- Admin catalog page: `/admin` (not `/catalog` — "admin" semantically matches the admin-only access model and is consistent with future admin expansions like queue view in V2)
- API routes pattern: `/api/parts` with sub-routes (consistent with Phase 3/4 pattern):
  - `GET /api/parts` — fetch all parts (with optional status filter via query param `?status=ready`)
  - `PATCH /api/parts/[id]` — update metadata
  - `DELETE /api/parts/[id]` — hard delete (DB + S3)
  - `POST /api/parts/[id]/archive` — soft delete (set status='archived')
  - `POST /api/parts/[id]/retry` — reset to pending + enqueue

## Accessibility Requirements

- All `<img>` elements: meaningful `alt` attribute — table thumbnails: `alt={name}`, Sheet thumbnail: `alt={"Vorschau: " + name}`
- Dropdown trigger button: `aria-label="Aktionen für {name}"`
- Search input: `aria-label="Teile suchen"` (label is visually hidden via placeholder)
- AlertDialog uses Radix built-in focus trap and aria roles — no additional work needed
- Sheet uses Radix built-in focus trap — ensure first focusable element is the Name input
- Status badges: include visually-hidden text supplement for screen readers if icon-only is used (not applicable here as badges include text)
- Tab count badges: `aria-label="{count} Teile"` on each Badge inside TabsTrigger
