## Error-State-Muster (Kernstück dieser Phase)

Dieser Abschnitt definiert den Standard für alle Fehlerzustände. Der Executor
wendet diese Muster konsistent auf Upload, Kamera-Suche und Admin-Katalog an.

### Fehler-Taxonomie

| Klasse | Auslöser | Muster | Platzierung |
|--------|----------|--------|-------------|
| **Inline-Validierung** | Dateigröße, Dateiformat, Pflichtfeld leer | `<p className="text-sm text-destructive">` unter dem Feld | Direkt unter dem Input |
| **Inline-Alert** | Duplikat-Upload (409), STEP-Worker-Fehler (status=failed) | `<Alert variant="destructive">` + Icon + Text + optionaler Action-Button | Innerhalb der Card, über dem Submit |
| **Page-Level-Error** | Seite konnte Daten nicht laden (usePartDetail fehlschlägt) | `<Alert variant="destructive">` mit Reload-Hinweis | Oberhalb des Seitencontents |
| **Toast** | Erfolgreiche Aktion (Speichern, Archivieren, Retry gestartet) | `sonner` toast — nur für Erfolg, NIE für Fehler | Rechts unten (Toaster in layout.tsx) |

### Fehler-Copywriting-Muster

**Struktur jeder Fehlermeldung:** `[Was ist passiert] — [Was der Nutzer tun soll]`

Die folgenden Texte sind verbindlich. Der Executor darf Texte nicht durch
generische Alternativen ersetzen.

#### Upload-Fehler (UploadForm.tsx)

| Situation | Aktueller Text | Phase-10-Standard |
|-----------|---------------|-------------------|
| Datei > 100 MB | "Datei überschreitet die maximale Größe von 100 MB." | BEIBEHALTEN — erfüllt SC-3 |
| Falsches Format | "Nur STEP-Dateien (.step, .stp) werden akzeptiert." | BEIBEHALTEN |
| Duplikat (409) | "Diese Datei existiert bereits — Teil-ID: {id}" | VERBESSERN → "Diese Datei wurde bereits hochgeladen. Zum vorhandenen Eintrag: [Link zu /parts/{id}]" |
| Worker failed | "Die Verarbeitung ist fehlgeschlagen. Bitte prüfe die STEP-Datei und versuche es erneut." | ERWEITERN → Alert mit Retry-Button (siehe unten) |
| Netzwerkfehler | "Upload fehlgeschlagen: {technische Meldung}" | VERBESSERN → "Upload fehlgeschlagen. Bitte Verbindung prüfen und erneut versuchen." (technische Details entfernen) |
| Polling-Timeout | "Die Verarbeitung dauert länger als erwartet. Seite neu laden, um den Status zu prüfen." | BEIBEHALTEN |

#### STEP-Verarbeitungsfehler (SC-1 — Kernziel)

Wenn `status === 'failed'` — verbindliches Alert-Markup:

```
[Alert variant="destructive"]
  [AlertCircle h-4 w-4]
  [AlertTitle] Verarbeitung fehlgeschlagen [/AlertTitle]
  [AlertDescription]
    Die STEP-Datei konnte nicht verarbeitet werden.
    Mögliche Ursachen: leere Geometrie, nicht unterstütztes STEP-Format, oder korrupte Datei.
    [Button variant="outline" size="sm"] Erneut versuchen [/Button]
  [/AlertDescription]
[/Alert]
```

Der "Erneut versuchen"-Button ruft POST /api/parts/{id}/retry auf (bereits
in Phase 5 implementiert) und setzt die Phase zurück auf 'polling'.

#### Kamera-Fehler (CameraCapture.tsx)

| Situation | Aktueller Text | Phase-10-Standard |
|-----------|---------------|-------------------|
| Kamerazugriff verweigert | "Kamerazugriff verweigert. Bitte erlaube den Kamerazugriff in den Browser-Einstellungen oder wähle ein Foto aus der Galerie." | BEIBEHALTEN — präzise und actionable |
| Kamera startet nicht | "Kamera konnte nicht gestartet werden. Wähle ein Foto aus der Galerie." | BEIBEHALTEN |
| Suche Timeout (AbortError) | "Suche hat zu lange gedauert. Bitte erneut versuchen." | BEIBEHALTEN |
| Suche Netzwerkfehler | "Suche fehlgeschlagen. Bitte überprüfe deine Verbindung und versuche es erneut." | BEIBEHALTEN |
| Nur Bilddatei erlaubt | "Nur Bilddateien erlaubt." | VERBESSERN → "Nur Bilddateien (JPEG, PNG) erlaubt." |
| HTTP-Fehler (non-2xx) | throw new Error(`HTTP ${res.status}`) → generische Meldung | VERBESSERN → "Suche fehlgeschlagen (Server-Fehler). Bitte erneut versuchen." |

## Loading-State-Muster

Alle Ladezustände folgen diesem Standard:

| Kontext | Muster | Dauer-Hinweis |
|---------|--------|---------------|
| Thumbnail lädt | `<Skeleton className="w-full h-full">` — bereits in SearchResultCard + UploadForm | Kein Text |
| Erster Kamera-Start | `<Skeleton className="w-full aspect-[4/3]">` + Text darunter | "Kamera wird aktiviert..." |
| STEP-Verarbeitung pending/processing | Badge + Beschreibungstext (bereits vorhanden) | "3D-Ansichten werden berechnet. Dies kann 30–120 Sekunden dauern." |
| Suche läuft (Erst-Suche) | `<Loader2 className="animate-spin h-8 w-8">` + Text | "Suche läuft..." |
| Suche läuft (Re-Suche) | Overlay mit `bg-background/70` + Spinner (bereits vorhanden) | Kein zusätzlicher Text |
| Seite lädt (PartDetail) | Skeleton-Blöcke mit identischen Dimensionen wie Ziel-Content | Kein Text |
| Admin-Katalog (1000+ Teile) | Pagination bleibt bei 20 Einträgen pro Seite — KEIN virtuelles Scroll | Ladezeit < 2s durch serverseitige Pagination |

**Skeleton-Regel:** Skeletons haben immer dieselben Dimensionen wie der geladene Inhalt.
Kein Layoutshift beim Laden.

## Mobile-Touch-Interaktions-Standards (SC-2)

Diese Standards gelten für alle Seiten — besonders für die Kamera-Suche auf
einem Mid-Range-Android in einer Werkstattumgebung.

### Touch-Target-Mindestgrößen

| Element | Mindestgröße | Tailwind-Klasse |
|---------|-------------|-----------------|
| Primäre Buttons | 44×44px | `min-h-[44px]` (shadcn Button default: h-10 = 40px → muss überschrieben werden) |
| Kamera-Aufnahme-Button | 48×full | `h-12 w-full` — bereits vorhanden |
| Badge-Links (SearchResultCard) | 44×44px Touch-Area über die gesamte Card | Card ist bereits vollständig anklickbar via Link-Wrapper |
| File-Input-Button | 44px Höhe | `min-h-[44px]` — bereits vorhanden |

**shadcn Button Size-Override für Phase 10:**
Wenn `size="default"` (h-10 = 40px) auf mobil-kritischen Buttons,
muss `className="h-11"` (44px) oder `size="lg"` (h-11) verwendet werden.
Ausnahme: Buttons innerhalb von Dialogs/Sheets — dort ist 40px akzeptabel
(Desktop-Kontext).

### Kamera-Vorschau (CameraCapture — SC-2)

- Framing-Overlay (`inset-[10%]`, weißer Rahmen) bleibt bei schlechter Beleuchtung sichtbar durch `border-white/70`
- Kein Text im Kamera-Overlay — Text auf Displays bei Werkstattbeleuchtung schlecht lesbar
- Video-Element: `playsInline muted autoPlay` — bereits korrekt implementiert
- Maximale Vorschau-Breite: `max-w-sm` (384px) — ausreichend für alle Standard-Handyformate

### Schriftgrößen auf Mobile

- Keine `text-xs` (12px) für interaktionsrelevante Texte (Buttons, Labels, Fehlermeldungen)
- `text-xs` erlaubt nur für: Metadaten-Hinweise ("Maximale Dateigröße: 100 MB"), Timestamps, sekundäre Beschriftungen
- Fehlermeldungen: `text-sm` (14px) — verbindlich

## Datei-Validierungs-UX (SC-3)

Die 100-MB-Grenze wird ausschließlich am Form-Level geprüft — kein Netzwerk-Request.

| Prüfpunkt | Zeitpunkt | Muster |
|-----------|-----------|--------|
| Dateigröße > 100 MB | `onChange` des File-Inputs (sofort bei Dateiauswahl) | `<p className="text-sm text-destructive">` unter dem Input |
| Falsches Format (.xyz statt .step/.stp) | `onChange` des File-Inputs | `<p className="text-sm text-destructive">` unter dem Input |
| Keine Datei ausgewählt bei Submit | `onSubmit`-Handler | `<p className="text-sm text-destructive">Bitte eine STEP-Datei auswählen.</p>` |

**Phase-10-Verbesserung:** Validierung von Größe und Format muss auf `onChange`
des File-Inputs verschoben werden (derzeit in `onSubmit`). Der Nutzer sieht den
Fehler sofort bei Dateiauswahl — nicht erst nach Klick auf "Hochladen".

**Verbindlicher Fehlertext für Größenüberschreitung:**
"Diese Datei ist zu groß ({tatsächlicheMB} MB). Maximal erlaubt: 100 MB."
(Konkrete Dateigröße einblenden — actionable.)

## Performance-Standards (SC-4)

| Metrik | Zielwert | Umsetzung |
|--------|----------|-----------|
| Admin-Katalog Ladezeit bei 1.000+ Teilen | < 2s | Serverseitige Pagination: 20 Einträge/Seite, `LIMIT 20 OFFSET n` im SQL |
| Thumbnail-Ladezeit | Nicht blockierend | Lazy Loading via useEffect — bereits implementiert |
| Suche End-to-End | < 5s (bereits SC aus Phase 6) | AbortController nach 30s — bereits implementiert |
| Upload-Response | < 2s (HTTP 202, bereits SC aus Phase 3) | Keine UI-Änderung nötig |

**Pagination-Implementierungsregel:**
`GET /api/parts` muss `?page=N&limit=20` unterstützen. CatalogTable zeigt
Pagination-Controls (shadcn Pagination-Komponente — bereits installiert).
Kein Client-seitiges Filtern über alle Datensätze.
