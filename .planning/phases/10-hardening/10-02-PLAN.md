**Gruppe B — HTTP-Fehler in handleSearch und handleSearchWithLimit:**
In beiden Funktionen den catch-Block erweitern. Aktuell wird unterschieden zwischen AbortError und "allem anderen". "Alles andere" schließt HTTP-Fehler (throw new Error(`HTTP ${res.status}`)) ein, was falsch als Netzwerkfehler dargestellt wird.

Neues Muster für beide catch-Blöcke:
```tsx
} catch (err) {
  let msg: string
  if (err instanceof DOMException && err.name === 'AbortError') {
    msg = 'Suche hat zu lange gedauert. Bitte erneut versuchen.'
  } else if (err instanceof Error && err.message.startsWith('HTTP ')) {
    msg = 'Suche fehlgeschlagen (Server-Fehler). Bitte erneut versuchen.'
  } else {
    msg = 'Suche fehlgeschlagen. Bitte überprüfe deine Verbindung und versuche es erneut.'
  }
  setErrorMessage(msg)
  setPhase('error')
} finally {
  clearTimeout(timeoutId)
}
```

Wichtig: Beide catch-Blöcke (handleSearch und handleSearchWithLimit) identisch anpassen.

```tsx
// onChange-Validierung (SC-3): sofortige Prüfung bei Dateiauswahl
const handleFileChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  const file = e.target.files?.[0]
  if (!file) {
    setFileError(null)
    return
  }
  if (file.size > MAX_FILE_BYTES) {
    setFileError(`Diese Datei ist zu groß (${Math.round(file.size / 1024 / 1024)} MB). Maximal erlaubt: 100 MB.`)
    return
  }
  if (!STEP_EXT_RE.test(file.name)) {
    setFileError('Nur STEP-Dateien (.step, .stp) werden akzeptiert.')
    return
  }
  setFileError(null)
}
```
