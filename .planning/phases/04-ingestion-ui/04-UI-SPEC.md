### Responsive Behavior

- Mobile (< 1024px `lg`): Single column — form first, status tracker below (stacked). Status tracker becomes visible as a second block below the form after submit.
- Desktop (≥ 1024px `lg`): 2-column grid side by side as specified in D-03.
- Status tracker visibility is controlled via React state (not CSS `hidden` class alone) — the component renders null before first submit, then renders the card.

## Interaction Contract

### Upload Flow (D-09)

| Step | Trigger | Visual Change |
|------|---------|---------------|
| 1 | User fills form + clicks "Hochladen" | Button shows `<Loader2 className="animate-spin" />`, becomes disabled |
| 2 | SHA-256 computed (browser, ~100ms) | No visual change — too fast |
| 3 | POST /api/upload/init → success | Progress bar appears at 0%, status tracker card becomes visible |
| 4 | PUT to S3 presigned URL | Progress bar increments from 0→100% using XMLHttpRequest progress events |
| 5 | POST /api/upload/confirm → HTTP 202 | Progress bar reaches 100%, Badge shows "pending" |
| 6 | Polling starts (D-04) | Status description shows "Warte auf Worker..." |
| 7 | Status = processing | Badge updates to "Wird verarbeitet...", Loader2 icon spins |
| 8 | Status = ready | Badge updates to "Fertig", Skeleton replaced by thumbnail `<img>` |
| 9 | Thumbnail loaded | "Neuer Upload" button appears (D-10) |

### Form Freeze (D-09)

After successful POST /api/upload/confirm, all form fields receive `disabled` prop. The submit button remains disabled. The form is NOT hidden — filled values remain visible so the engineer can confirm what was uploaded.

### Duplicate Error (D-11)

When POST /api/upload/init returns HTTP 409:
- An `<Alert variant="destructive">` appears immediately below the file input area
- Copy: `Diese Datei existiert bereits — Teil-ID: [existing_part_id]`
- Form fields remain enabled and editable
- The file input is NOT cleared automatically
- No toast is shown for this error (explicit in D-11)

### Polling Logic (D-04, D-05, D-06)

Implemented as `usePartStatus(partId: string | null)` custom hook in `src/hooks/use-part-status.ts`:
- Interval: 2s for first 30s → 5s after that
- Stop condition: `status === 'ready' || status === 'failed'`
- Timeout: 5 minutes → polling stops, warning message appears
- Timeout warning copy: "Die Verarbeitung dauert länger als erwartet. Seite neu laden, um den Status zu prüfen."
- Network errors during polling: silent retry — do not show error toast on transient failure; show error only after 3 consecutive failures

### Thumbnail Display (D-07, D-08)

- Only `view_0.png` (Frontansicht) is displayed
- Flow: when `status === 'ready'`, fire GET `/api/parts/[id]/thumbnail` → receive presigned S3 URL → render `<img src={url} alt="Frontansicht" />`
- While URL is loading: `<Skeleton className="w-48 h-48" />`
- Image display: `<img className="w-48 h-48 object-contain rounded-md border" />`
- No fallback if thumbnail fetch fails in Phase 4 (deferred to Phase 10 Hardening)

### Reset (D-10)

"Neuer Upload" button appears only after `status === 'ready'`. On click:
- All form fields reset to empty/defaults via `react-hook-form` `reset()`
- Status tracker card becomes hidden again (React state → null)
- `partId` state cleared
- Polling hook stops (effect cleanup)

## Zod Validation Schema

For the upload form (react-hook-form + zod resolver):

```typescript
// Field constraints — executor implements exactly these
const uploadFormSchema = z.object({
  name: z.string().min(1, "Bezeichnung ist erforderlich.").max(200),
  partNumber: z.string().max(100).optional(),
  project: z.string().max(200).optional(),
  status: z.enum(["pending", "processing", "ready", "failed"]).default("pending"),
  // file: handled outside zod (uncontrolled input + manual validation)
})
```

File validation (manual, not zod — runs before form submit):
- Accept: `.step`, `.stp` (MIME: `application/step`, `application/x-step`, or check extension)
- Max size: 100 MB (`104_857_600` bytes)

## New API Routes (Phase 4 adds)


Response shape:
```typescript
{ url: string }  // presigned S3 URL, 60s lifetime
```

The `<img>` tag renders this URL directly. No proxy.
